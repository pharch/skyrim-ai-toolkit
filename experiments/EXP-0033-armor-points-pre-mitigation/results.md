# Results

- **Build:** GOG Skyrim AE 1.6.1179.0, executable SHA-256 `9b0fc7880c4b12d436bfb59bcae64868f176dbc04010adbd9bc2ecb64bc8ed3f`. Queries used the configured existing Ghidra project read-only with auto-analysis disabled.
- **Points source:** `FUN_1406bcaa0` builds HitData at `[RSP+0x50]`. At `0x1406bcf00`, the player receiver's unblocked AV11/AV12 call loads points from `[RSP+0xA4]`, which is HitData `+0x54`, `physicalDamage` ([EV-0217], [EV-0222], [EV-0285]).
- **Normal source order:** Both the default `FUN_1407dd220` and alternate `FUN_1407dd5b0` paths reach `FUN_1407ddf50` after their earlier `FUN_1407ded20` adjustment. The common helper copies `totalDamage` (`+0x50`) into `physicalDamage` (`+0x54`) before applying AV39 and armor-base-factor reduction to `totalDamage` ([EV-0222], [EV-0223], [EV-0261]). H1 is falsified for these paths; H2 is supported with the scope stated here.
- **Conditional exception:** After HitData construction, `FUN_1406bcaa0` can call `FUN_1407dda40`. That helper's `MOV qword ptr [RCX+0x50], 0` clears both 32-bit fields at `+0x50` and `+0x54`, plus a separate field at `+0x58`. The helper is called only through an actor/process condition involving a nested process byte at `+0x324`, a zero write to that byte, Actor virtual slot `+0x718`, and process byte `+0x139`; these offsets are not yet mapped to gameplay semantics ([EV-0285]). H3 is supported as a static conditional path.
- **Sink:** The existing GOG PlayerCharacter `UseSkill` override rejects non-positive points before skill progression ([EV-0220], [EV-0221]). This makes the conditional zero clear a possible zero-points route in code, not a demonstrated vanilla XP exploit.
- **Not observed:** Steam 1.6.1170 native equivalence, live calls, actual raw AVSK, armor protection, a qualifying armor set, or whether the clear branch can coexist with useful protection.
