# EXP-0039 — Physical trap native hit handoff

**Status:** The GOG native binding is traced into common HitData construction, a shared post-resolver actor-hit handler, a runtime-initialized AV11/AV12 callback, a conditional Health-damage route, the matching Actor/PlayerCharacter targets for slots `0x99`, `0x5C`, and `0x70`, and the first ActorMagicCaster update methods. These mapped bodies and bounded direct callees show no AV11/AV12 award or direct return to the known resolver. Nested concrete object targets, other receiver objects, and live mitigation/XP remain unresolved.

**Question:** Does a positive physical trap impact on the player reach the armor XP branch, or does it use a distinct receiver path after common HitData construction?

**Current result:** Skyrim.esm `TrapFallingRockLg01` configures positive tiered damage, and its PEX route calls `ObjectReference.ProcessTrapHit` after impact checks. In GOG AE 1.6.1179, the exact native target dispatches through PlayerCharacter slot `0x58`, builds HitData through `FUN_1407dd110`/`FUN_1407ddf50`, then reaches `FUN_1406b9df0`. The known AV11/AV12 resolver `FUN_1406bcaa0` also calls that handler after its player receiver branch, while the captured trap route enters the handler directly. The handler's helper `FUN_1406b49d0` has a conditional Health (`0x18`) `HandleHealthDamage` route. Its ActorValue callback table maps AV11/AV12 to `FUN_1406b65c0`, then Actor slot `0xCA`; the selected PlayerCharacter implementation updates fields/container state without a visible `UseSkill` award or direct return to `FUN_1406bcaa0`. EV-0296 maps the Actor/PlayerCharacter receiver slots `0x99`, `0x5C`, and `0x70`, plus the nested PlayerCharacter slot-`0x71` predicate; EV-0297 follows the first ActorMagicCaster update methods reached from slot `0x5C`. These selected bodies and bounded direct callees show no AV11/AV12 award or direct return to the known resolver. The HitData `+0x38` pointer's concrete subtype and nested virtual targets remain unresolved; live mitigation/XP remain unmeasured ([EV-0261], [EV-0291]–[EV-0297]).
